# Domain docs

## Layout

This repository uses a single context:
- GLOSSARY.md at the repository root.
- Architecture decision records under docs/adr/.

## Before exploring

Read GLOSSARY.md and ADRs relevant to the area being explored.
If they do not exist, proceed silently. Create them lazily through
domain-modeling when terms or decisions are resolved.

## Vocabulary

Use glossary terms when naming domain concepts in code, tests,
issues, and proposals. If a needed term is missing, reconsider
whether it belongs or note the gap for domain-modeling.

## Decisions

If a proposal contradicts an existing ADR, identify the ADR and
explain why the decision should be revisited.
